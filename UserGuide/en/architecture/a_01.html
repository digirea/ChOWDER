Introduction

This document describes the design of the cooperative workspace driver and the cooperative behavior framework.

System Configuration

Overall Configuration

This system is a client-server program using node.js and websockets, and provides a huge screen space as a virtual display where multiple applications and multiple users can collaborate. The configuration diagram is shown below

Server and Client Roles

Roles of the Server

  • HTTP communication - sending HTML pages and other information to the client
  • Websocket communication - Communicate with the client's controller and display using the websocket protocol.
  • Database input/output - Saves image data and text data sent by the client in redis and makes them persistent.
  • Server-side rendering - The website with the submitted URL is rendered on the server side using phantomjs and saved as a png image.

Client - Role of the controller

  • Registering and deleting displays
  • Metadata editing operations such as moving, scaling, etc.
  • Registration and deletion of contents (image data, text, URL)
  • Metadata editing operations such as moving, scaling, etc.
  • Setting the number of display divisions
  • Downloading content data

Role of Client-Display

  • Register own window as a display to the server
  • Display content as configured in the controller.

Server Configuration

Server

The server supports HTTP/HTTPS communication and websocket communication (ws/wss) using node.js. The ports for accepting each communication method are divided into different ports.

Communication method Usage Initial port
HTTP Static pages and static contents 80
Websocket(ws) Providing dynamic contents via ChOWDER API, operation, etc. 80
HTTPS Provision of static pages and static contents 443
Websocket(wss) Provide dynamic contents via ChOWDER API, operation, etc. 443

The port number and permission can be changed in the server configuration file.

Database

The database uses redis for fast response.
The data is stored using "Data Structure" for the data storage method

Other Software

PhantomJS and phantomjs, an npm wrapper for phantom.js, are used for web page rendering.
Server-side rendering is used for web page rendering.

Overall Design

ChOWDER is designed based on Flux, and the call flow is as shown in the figure below.

Most operations in ChOWDER are described in action.js. For example, if you want to add a GUI and perform an arbitrary operation, you call a function defined in action.js from the GUI.

In addition, store.js holds the data and executes the business logic, but since the server-side RedisDB is the true store, the client-side store.js behaves as a cache.

As for GUI, ShadowDOM should be used, but since ChOWDER was originally developed using (old) pure js, ShadowDOM is not used, and each component is separated as a component.
