Server Settings

Basic Server Settings

The server program reads the server/setting.json file at startup to configure various settings. 

{
    "wsMaxMessageSize": 67108864,
    "reductionResolution" : 1920,
    "enableMeasureTime" : false,
    "stunServerUrl" : "",
    "turnServerUrl" : "",
    "turnServerUsername" : "",
    "turnServerCredential" : "",
    "enableHTTP" : true,
    "enableSSL" : true,
    "HTTPPort" : 80,
    "SSLPort" : 443,
    "enableCORS" : true,
    "VRMode" : 'cylinder',
    "reduceUpdate": false,
    "reduceInterval" : 500,
    "tileviewerCursorSize" : 100
}
    Setting name Overview Default value Maximum Minimum
    wsMaxMessageSize Sets the maximum message size that the server can send and receive at one time. 67108864 -- --
    reductionResolution Sets the size of the reduced image for large image data. If large image data larger than this size is registered, a reduced image will be generated, and depending on the display resolution, the reduced image will be used for display. 1920 -- --
    enableMeasureTime Enable/disable time log output. If time log output is enabled, log files are output to tileimage/log and server/log. Also, you can download the logs from the Display on the Display. false -- --
    stunServerUrl Specify the URL of the STUN server to be used for WebRTC connection. For WebRTC, see “Add a video file”. -- --
    turnServerUrl Specify the URL of the TURN server to be used for WebRTC connection. -- --
    turnServerUsername Specify the User Name for authentication of the TURN server to be used for WebRTC connection. -- --
    turnServerCredential Specify the password for authentication of the TURN server to be used for WebRTC connection. -- --
    enableHTTP Specify whether to enable HTTP communication. true -- --
    enableSSL Specify whether to enable HTTPS communication. HTTP and HTTPS (SSL) communications can be used simultaneously. true -- --
    HTTPPort Specify the port number to be used for HTTP communication; the same port is used for Websocket(ws) communication. 80 0 65535
    SSLPort Specify the port number to be used for HTTPS communication; the same port is used for Websocket(ws) communication. 443 0 65535
    enableCORS Specifies whether CORS is allowed for web content published by the ChOWDER Server. true
    VRMode Specify the VR mode to be used. Currently available values are “plane” (flat view), “cylinder” (curved view), or “360” (360-degree view).
    Please refer to the section “Setting up VR mode” for details.     		cylinder
    reduceUpdate Set to true to reduce the frequency of various update notifications from the Controller. false
    reduceInterval If reduceUpdate is true, specify the maximum waiting time in milliseconds to reduce the frequency of update notifications. 500
    tileviewerCursorSize Specify the cursor size in relative value when RemoteCursor function is used in TileViewer. 100

Administrator Initialization

The administrator controller can be set at startup.
By default, the administrator password is set to "admin".
After logging in, changes can also be made from the Management screen.

Administrator configuration file

You can add/delete administrators at startup by creating an admin.json file in the top level folder of ChOWDER ( the folder containing README.md ). The format of admin.json is as follows ( also described in the admin.json.org file)

{
    "administrator" : {
        "command" : "add",
        "password" : "admin"
    },
    "administrator2" : {
        "command" : "delete",
        "password" : "admin2"
    }
}

In this example, the controller "administrator" is added (overwritten) and "administrator2" is deleted.

To add (overwrite) a controller with the administrator name as a key, use "command" : "add",
to delete a controller use "command" : "add", to delete a controller use "command" : "delete".
To delete, enter "command" : "delete". When adding, "password" is required.
This json file is loaded when ChOWDER is started, and the administrator is registered or deleted in the DB.
Once ChOWDER is started and the administrator is registered in the DB, the admin.json file is no longer needed.
Also, for `Moderator` and `Attendee`, you will not be able to log in until you set your password in the settings screen after logging in separately. If you wish to use the `Moderator` and `Attendee` privileges, please set the password in advance as a user with Admin privileges.
For details, see “Password Settings” below.
